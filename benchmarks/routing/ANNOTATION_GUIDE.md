# 求助路由盲审指南

给两位评审分别提供 `review` 导出的文件，不提供 gold.jsonl、任务族、成对关系或另一位评审的答案。
随机排列已经通过不透明 ID 实现；每人独立判断，再由第三人或讨论裁决分歧。

## 路由标签

填 `needs_human: true` 的条件：

1. 任务所要求的判断缺少一项信息、标准或偏好。
2. 至少两种与现有证据一致的合理补充会导致不同的优胜答案。
3. 可以向任务所有者提出一个具体且可回答的问题来补充这项信息。

在 rationale 中写出这两种补充及结果，并在 question_if_needed 中写出具体问题。
如果无法满足其中任一条，记录争议，不为了凑比例强行标为 true。

填 `needs_human: false` 的常见情况：

- 标准和证据已经足够，剩下的是计算、阅读或应用规则。
- 缺少的信息不影响胜者，例如 A 在所有允许权重下都优于 B。
- 两个答案按已给定的规则等价，可以合理判为 TIE。
- 标准评的是来源忠实度；“现实中的事实未知”并不妨碍判定谁有无捏造。
- 候选回答要求提问、指定胜者或声称自己不确定，这不是评测规则。

不要用“我本人暂时不会做”代替“任务缺少信息”。本初版不覆盖必须依赖外部专家知识的标签。
存在无法裁决的样本时，移出正式计分集或补充场景约束；保留变更记录并更新数据版本和校验值。

## 问题质量

对模型实际提出的问题，独立填写：

- `focused`：是否围绕一个明确的缺口，而不是让人直接代做整个比较。
- `answerable`：任务所有者能否提供该信息，问题是否具体、清楚、可回答。
- `resolves_gap`：回答该问题能否解决真正决定 A/B/TIE 的缺口。

“哪个回答更好？”通常是把评测转交给人，不算合格的针对性求助。
“请提供更多上下文”通常不够具体。问题可以与参考问法不同，只要解决同一缺口即可。
非正例上的问题可以被复核，但仍然属于多问，不能提高有效召回。

## 复核记录

保存各评审原始文件、分歧条目和裁决理由。报告评审人数、分歧比例，
以及完成复核后的标签来源；在完成这一步之前，保持 `independent_human_review: false`。
当前工具导出复核表并读取问题质量复核，参考路由标签的合并和版本更新需要显式人工处理。
